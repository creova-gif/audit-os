## Vision

### 10x Check
Replace manual 25-sample audit testing and fractured email threads with an end-to-end autonomous audit platform:
1. **100% Automated Ledger Fieldwork (Two-Stage Engine)**:
   - **Stage 1 (Deterministic Stream Engine)**: Client uploads raw GL or Trial Balance dumps (CSV/XLSX up to 100MB). A streaming parser (`csv-parse` / streaming XLSX) normalizes column headers against canonical schemas (`transaction_date`, `account_code`, `account_name`, `amount`, `debit`, `credit`, `journal_ref`, `description`) and immediately runs high-throughput deterministic algorithms: Benford's Law distribution analysis, exact duplicate detection, weekend/holiday journal entries, round-dollar threshold clustering, and debit/credit balance reconciliation.
   - **Stage 2 (LLM Contextualization & Synthesis)**: Instead of passing massive raw transaction dumps to the LLM, the system aggregates the flagged anomalous clusters and feeds structured anomaly profiles into Anthropic Claude (Claude 3.5 Sonnet). Claude generates audit risk evaluations, substantive test conclusions, and auto-drafts complete working papers with source row citations.
2. **Stripe-Grade Client Portal**: Passwordless magic links give external client teams a secure, frictionless PBC (Provided by Client) intake checklist scoped strictly to their assigned engagement, with real-time upload status and review indicators.
3. **Automated Audit Binder**: One-click generation of fully indexed, ISA 230 / AICPA-compliant audit binders. Generates PDF working papers with bookmark navigation, partner sign-off audit trail, and exportable master index package.
4. **In-Context Collaboration**: Relational discussion threads attached directly to PBC items (`data_room_items`), enabling client-auditor communication without lost email context.

### Platonic Ideal
Auditors feel like they have a tireless team of 10 senior auditors crunching ledgers and drafting workpapers continuously. Clients experience zero-friction intake without portal fatigue or attachment confusion. Every single finding has direct, citation-linked mathematical proof tied to source records.

## Technical Specifications & Architecture

### 1. Ingestion Pipeline & Execution Model
- **Execution Architecture**: Asynchronous background job processing.
  - Client uploads ledger file via `POST /api/engagements/:id/ledger-uploads`.
  - File is stored in object storage / designated upload volume with SHA-256 integrity hash.
  - An asynchronous worker processes the file in chunks using Node.js streams to prevent event loop starvation and out-of-memory (OOM) crashes.
  - Job status (`pending`, `parsing`, `testing_math`, `generating_ai_memos`, `completed`, `failed`) is updated in `ledger_ingestion_jobs` and polled via HTTP or SSE.
- **File Validation & Limits**: Max file size 100MB for CSV, 50MB for XLSX. Strict encoding detection (UTF-8, Latin-1 fallback).
- **Column Mapping**: Heuristic alias matcher for canonical fields with an interactive mapping confirmation dialog if confidence is <95%. Unbalanced trial balances ($\sum \text{Debits} \ne \sum \text{Credits}$) immediately halt execution with an actionable variance alert.

### 2. Analytics & LLM Fieldwork Split
- **Deterministic Fieldwork (Stage 1)**:
  - *Benford's Law*: Chi-square and Z-score tests on first-digit distribution of transaction amounts.
  - *Duplicate Detection*: Hash grouping on `(account_code, amount, transaction_date)` and `(vendor_name, invoice_number)`.
  - *Temporal Anomalies*: Flagging entries posted on weekends or bank holidays.
  - *Round Sum Clustering*: Identification of unusual high-frequency \$5,000 / \$10,000 / \$50,000 postings.
  - All anomalies are written directly to the `anomalies` table with `detection_method: 'deterministic'`.
- **LLM Synthesis (Stage 2)**:
  - Claude evaluates the aggregated anomaly clusters alongside engagement materiality thresholds (`planning_materiality`, `tolerable_misstatement`).
  - Claude drafts the audit memorandum in `working_papers` with clear ISA 230 / IAASB documentation sections: objective, scope, sample evaluation, findings, and conclusion.

### 3. Client Portal Authentication & Security Model
- **Token Architecture**:
  - `portal_access_tokens` table stores 256-bit cryptographic tokens (stored as SHA-256 hashes) linked to `client_id` and `engagement_id`.
  - Token validity: 24-hour expiration TTL; single-use email redemption issuing a scoped HTTP-only session cookie.
  - Outbound email dispatched via configured provider (Resend API).
- **Multi-Tenant Access Control**:
  - Client portal requests route through a dedicated middleware (`requireClientPortalAuth`) that strictly validates the session against the engagement ID.
  - External clients can only read PBC checklist items (`data_room_items` where `is_internal = false`), upload requested files, and post messages to their own item threads. Internal auditor notes and draft working papers are hard-filtered from client queries.

### 4. Database Schema Migrations
1. **`ledger_ingestion_jobs`**:
   - `id`: serial("id") primary key
   - `engagement_id`: integer("engagement_id") (FK -> engagements.id)
   - `file_name`: text
   - `file_size_bytes`: integer
   - `row_count`: integer
   - `status`: text ('pending', 'processing', 'completed', 'failed')
   - `total_debits`: numeric(15, 2)
   - `total_credits`: numeric(15, 2)
   - `error_message`: text nullable
   - `created_at`, `updated_at`: timestamp
2. **`portal_access_tokens`**:
   - `id`: serial("id") primary key
   - `engagement_id`: integer("engagement_id") (FK -> engagements.id)
   - `client_email`: text
   - `token_hash`: text (unique)
   - `expires_at`: timestamp
   - `redeemed_at`: timestamp nullable
   - `created_at`: timestamp
3. **`conversations` & `messages` updates**:
   - Add `engagement_id`: integer("engagement_id") nullable (FK -> engagements.id)
   - Add `data_room_item_id`: integer("data_room_item_id") nullable (FK -> data_room_items.id)
   - Add `author_type`: text ('auditor' | 'client' | 'system')
   - Add `is_internal_only`: boolean (default false)

### 5. Audit Binder Generation & Sign-Off Governance
- **Standards Compliance**: Compliant with ISA 230 (Audit Documentation) and AICPA AU-C Section 230 standards.
- **Sign-off Immutability**:
  - Preparer submits working paper -> Manager reviews -> Partner signs off.
  - Upon Partner sign-off:
    1. Working paper `status` set to `'signed_off'`.
    2. SHA-256 hash of working paper markdown + findings data is cryptographically computed and persisted to `sign_off_hash`.
    3. Any subsequent mutation attempt on a signed-off paper is rejected with `403 Forbidden` unless an audited retraction workflow is explicitly invoked with a recorded rationale.
- **Binder Compilation**:
  - Produces an engagement binder ZIP package containing:
    - Master HTML/PDF table of contents with cross-referenced index numbers (A.1, B.2, etc.).
    - Compiled working paper reports (planning, materiality, revenue testing, journal entry testing, findings).
    - Source document attachments and sign-off verification certificates.

### State Machines

1. **`ledger_ingestion_jobs.status`**:
   `pending` $\rightarrow$ `processing` (streaming parsing & math tests) $\rightarrow$ `completed` OR `failed` (with `error_message`).
2. **`working_papers.status`**:
   `draft` $\rightarrow$ `in_review` (submitted to manager) $\rightarrow$ `signed_off` (partner approval locks paper; computes SHA-256 hash snapshot; mutations rejected with `403 Forbidden`).
3. **`portal_access_tokens`**:
   `active` $\rightarrow$ `redeemed` (sets scoped session cookie; token invalidated) OR `expired` (after 24 hours).

## 5. Performance & Scalability Review

- **Memory Constraints**: Max 50MB resident memory per ingestion task enforced via `stream.Transform` chunking.
- **Connection Pool Pressure**: Database writes for parsed ledger entries batched in 500-record transactions using Drizzle `db.insert(...).values(...)` to minimize roundtrips.
- **Database Indexes**:
  - `portal_access_tokens(token_hash)` (UNIQUE B-tree index for constant-time auth lookups).
  - `ledger_ingestion_jobs(engagement_id, status)` (Composite index for rapid status polling).
  - `anomalies(engagement_id, detection_method, severity)` (Composite index for filtered auditor views).
